# Кратко для защиты

DataSource V2 — интерфейсы интеграции внешних источников со Spark SQL. Наш коннектор использует их напрямую, без read.text/csv и без V1 RelationProvider.

- TableProvider находит схему по двум строкам заголовка и создаёт таблицу.
- Table описывает схему и разрешённые операции; SupportsRead создаёт ScanBuilder.
- ScanBuilder строит план чтения Scan.
- Scan сообщает схему результата и предоставляет Batch.
- Batch делит чтение на InputPartition и предоставляет фабрику reader.
- InputPartition — сериализуемое описание работы для одной Spark task (путь, схема), а не содержимое файла.
- PartitionReaderFactory создаёт reader на исполнителе, не на драйвере.
- PartitionReader последовательно выполняет next/get/close, возвращая InternalRow. Строка преобразуется в UTF8String, LONG/DOUBLE — в Long/Double.

Схема берётся из второй строки: имена и типы реальны, порядок сохраняется. Первая строка PDBP/1 защищает от чужих форматов. При открытии партиции схема проверяется повторно. Ошибки данных содержат номер физической строки.

Writer — независимый Java AutoCloseable для создания нашего формата. Он не реализует SupportsWrite, WriteBuilder, BatchWrite и не участвует в Spark commit protocol. Это соответствует заданию: требуется собственный writer формата, а коннектор только читает.

Покажите DemoApp: 12 записей, фильтр >60 даёт 6, общая сумма 780; explain содержит BatchScan/PdbpBatchScan. Единственная capability — BATCH_READ. Фильтрацию и агрегацию выполняет Spark после чтения; pushdown отсутствует.

Почему одна партиция? Это минимальная полноценная архитектура V2. Чтение последовательно; интерфейсы позволяют позже добавить разбиение, но обещать параллельное чтение в текущей версии нельзя.

Почему escape? Каждая запись обязана занимать ровно одну физическую строку; переносы, слеш и разделитель внутри текста должны кодироваться однозначно. Codec общий для writer и reader.
